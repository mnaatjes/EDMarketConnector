# ADR 0010: Journal Telemetry Validation Framework

## 1. Title
ADR 0010: Journal Telemetry Validation Framework

---

## 2. Status
**Proposed**

---

## 3. Context
We are building a `MockJournalWriter` simulator to generate mock game logs and Journal State Snapshots (JSS) for testing. However, if our mock generator produces malformed JSON, incorrect key types, or schemas that do not match the real game's outputs, our integration tests will pass on "garbage data" but fail in production.

We need a systematic way to:
1. Validate that the mock files generated by our SDK strictly comply with the game's actual v37 specifications.
2. Extract structural JSON schemas from real-world game logs to use as baseline rules.
3. Warehouse real-world anonymized logs as "golden test articles" for regression testing.

---

## 4. Decision
We will implement an automated Journal Telemetry Validation Framework. This framework will be stored inside the `src/edmc/testing/` package, leveraging standardized Python validation libraries and staging real-world test logs.

### 4.1 Architecture & Directory Layout
* **Validation Sub-module (`src/edmc/testing/validation/`):** Houses validation schemas and check functions.
* **Dev Schema Extraction Tooling:** We will use `genson` in our developer environment to dynamically parse raw logs and generate JSON Schema definitions.
* **Validation Engine:** We will use `jsonschema` in our development dependencies to validate generated logs against the inferred schemas.
* **Golden Test Data Warehouse (`tests/data/journal/v37/`):** A dedicated directory for storing anonymized, real-world `Journal.*.log` files and companion snapshots (JSS) to serve as parsing baselines.

```text
src/edmc/testing/
└── validation/
    ├── __init__.py      # Exports validator functions
    ├── validator.py     # Main validator executor using jsonschema
    └── schemas/         # JSON Schema files (.json) for events/snapshots
```

### 4.2 Ingestion & ETL Workflow for Schema Generation
For developers to update validation rules:
1. **Extraction (ETL):** A utility script (`scripts/extract_schemas.py`) reads raw logs from a user-provided game directory, passes them to `genson`, and outputs JSON Schema drafts.
2. **Sanitization:** The script strips out sensitive data (CMDR names, FIDs, station names) before generating the schema and archiving samples.
3. **Storage:** The inferred schema is saved to `src/edmc/testing/validation/schemas/`, and sanitized log files are archived in `tests/data/journal/v37/` as test articles.

### 4.3 Validation Execution
* During test runs, whenever `MockJournalWriter` outputs an event, the test suite can optionally run `validate_event(event_name, payload)` or `validate_snapshot(snapshot_name, path)`.
* If a generated schema key or type deviates from the recorded standard (e.g. `FuelLevel` is written as a string instead of a float), the validator raises a `ValidationError`, halting the test.

---

## 5. Consequences

### Positive:
* **Contract Enforcement:** Guarantees that our mock generators never drift from the game client's actual data outputs.
* **Regression Protection:** Running tests against archived real-world logs ensures new parser versions do not break compatibility with historical game event structures.
* **Clean Typings:** The JSON Schemas can be leveraged in the future to automatically generate strict Pydantic model types for `src/edmc/domain/`.

### Negative:
* **Dependency Expansion:** Adds `jsonschema` to the development dependencies and requires `genson` for developers running extraction scripts.

---

## 6. Procedure & Implementation

1. **Update `pyproject.toml`:** Add `jsonschema` to the `dev` dependency table. Add `genson` to the `review` dependency table.
2. **Scaffold validation:** Create `src/edmc/testing/validation/` directories and empty `__init__.py` facades.
3. **Scaffold data warehouse:** Create the `tests/data/journal/v37/` directory to store anonymized test log articles.
4. **Develop Extraction Script:** Write `scripts/extract_schemas.py` using `genson` to allow automated telemetry schema generation.
